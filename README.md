# Gravity Moments — сайт

Односторінковий сайт без збірки й залежностей: звичайні HTML, CSS і JavaScript.
Щоб щось змінити, достатньо відкрити потрібний файл текстовим редактором.

---

## Що де лежить

| Файл | Що в ньому |
|---|---|
| `index.html` | Уся сторінка: тексти, секції, форма |
| `assets/css/main.css` | Вигляд: кольори, шрифти, відступи |
| `assets/js/prices.js` | **Ціни конструктора. Єдиний файл, який вам справді треба правити** |
| `assets/js/constructor.js` | Логіка конструктора. Не чіпати |
| `assets/js/main.js` | Меню, анімації, форма, аналітика |
| `assets/img/` | Картинки |
| `telegram-worker/` | Приймач заявок, живе окремо в Cloudflare |

## 1. Як змінити ціни

Відкрийте `assets/js/prices.js`. Усередині — тільки цифри й підписи, з поясненнями
українською. Логіка розрахунку лежить в іншому файлі, тому зіпсувати сайт правкою
цін майже неможливо.

Кожна стаття кошторису рахується так:

```
сума = (fixed + perGuest × кількість гостей) × коефіцієнти
```

- `fixed` — те, що не залежить від кількості людей (оренда, монтаж техніки)
- `perGuest` — те, що множиться на кожного гостя (їжа, посадка)
- `floor` — нижня межа: дешевше за цю суму стаття не покаже

**Правила правок:**
- міняйте тільки цифри;
- коми в кінці рядків і лапки не прибирайте;
- після правки обовʼязково зробіть два кроки нижче.

### Після будь-якої правки цін

1. У `prices.js` змініть дату в рядку `updated: '2026-09-11'` на сьогоднішню.
   Ця дата їде в кожну заявку — видно, за яким прайсом людина рахувала.
2. У `index.html` знайдіть `?v=20260912a` (чотири місця) і змініть на іншу дату,
   наприклад `?v=20261015a`.

**Другий крок — не формальність.** Без нього в тих, хто вже заходив на сайт,
у браузері лишиться стара версія з попередніми цінами.

## 2. Як додати фото кейсу

1. Покладіть фото в `assets/img/cases/` з іменем `case-1.jpg`, `case-2.jpg`, `case-3.jpg`.
2. В `index.html` знайдіть `<section id="cases"` і заберіть слово `hidden` у цьому рядку.
3. Замініть текст-заготовку справжніми історіями.

Картка сама підхопить фото, коли файл зʼявиться, — переверстувати нічого не треба.
Поки файлу немає, стоїть градієнт із монограмою, і це виглядає навмисно, а не зламано.

**Важливо:** у кейсах не має бути вигаданих відгуків. Порожня секція краща
за вигадану — з неї не виросте претензія.

### Фото Марини

Покладіть портрет у `assets/img/marina.jpg` — він сам стане в секцію «Про Марину».
Формат вертикальний, приблизно 4:5. Поки файлу немає, стоїть монограма.

---

## 3. Імена артистів

У секції «Артисти та зірки» є прихований блок «З ким уже працювали».
Щоб він зʼявився: в `index.html` знайдіть `id="feeNames"` і заберіть `hidden`,
а замість «Імʼя артиста» впишіть справжні імена.

Блок навмисно прихований: обіцянка «у нас є зірки» без жодного імені
працює проти нас.

## 4. Заявки: Telegram

Заявки з форми йдуть у Telegram через Cloudflare Worker — маленьку програму,
яка стоїть між сайтом і ботом. Вона потрібна, щоб токен бота не лежав
у відкритому коді сайту.

### Перший запуск

1. **Бот.** У Telegram напишіть `@BotFather` → `/newbot` → отримайте токен.
2. **Група.** Створіть групу «Gravity / заявки», додайте туди бота,
   напишіть у групу будь-яке повідомлення. Далі відкрийте в браузері
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` і знайдіть там `"chat":{"id":-100…}`.
   Це номер групи.
3. Впишіть цей номер у `telegram-worker/worker.js`, рядок `DEFAULT_CHAT_ID`.
4. З теки `telegram-worker` виконайте:
   ```
   npx wrangler secret put BOT_TOKEN
   npx wrangler deploy
   ```
5. Адресу, яку видасть `wrangler`, впишіть у `assets/js/main.js`
   у рядок `TG_ENDPOINT`.

### Перевірка перед запуском сайту

Відкрийте адресу Worker'а просто в браузері. У відповіді має бути:

```json
{"ok":true,"originAllowed":true,"chatConfigured":true,"tokenConfigured":true}
```

Якщо `originAllowed: false` — ваш домен не вписаний у список `ALLOWED`
у `worker.js`. **Це найчастіша причина, чому форма мовчки перестає приймати
заявки після переїзду на новий домен.** У списку мають бути одразу три адреси:
домен з `www`, домен без `www` і адреса на `github.io`.

Після зміни домену Worker треба розгорнути заново (`npx wrangler deploy`).

### Якщо заявка не дійшла

Сайт не робить вигляду, що все гаразд: людина бачить повідомлення про помилку
й прямі контакти Марини. Сама заявка при цьому зберігається в браузері
й відправиться автоматично при наступному відкритті сайту (протягом трьох діб).

## 5. Аналітика

У `assets/js/main.js` угорі є два порожні рядки:

```js
var GA4_ID    = '';     // 'G-XXXXXXXXXX'
var PIXEL_ID  = '';     // '1234567890'
```

Поки вони порожні — нічого не вантажиться й нічого не збирається.
Впишіть ідентифікатори, і воронка почне збиратися сама: події вже розставлені
по всій сторінці.

Що можна буде побачити: на якому кроці конструктора люди зупиняються,
який середній бюджет у заявках і з якого джерела приходять найдорожчі.

## 6. Що ще треба зробити перед запуском

- [ ] **Прибрати `<meta name="robots" content="noindex">` в `index.html`** — він ховає сайт від пошуковиків, поки той живе на тимчасовій адресі github.io.
- [ ] **Підтвердити ціни в `prices.js`.** Зараз там ринкові орієнтири.
      Поки Марина їх не перевірила — сайт публікувати не можна.
- [ ] Домен: купити, підключити до GitHub Pages, створити файл `CNAME`
      з адресою домену, вписати домен у `worker.js` → `ALLOWED`.
- [ ] Бот і група для заявок, `wrangler deploy`, перевірка через GET.
- [ ] `assets/img/favicon.png` — іконка сайту (512×512).
- [ ] `assets/img/og-cover.jpg` — картинка для месенджерів (1200×630).
      Без неї посилання в Telegram виглядає мертвим.
- [ ] Портрет Марини.
- [ ] Три текстові кейси.
- [ ] Імена артистів, які можна називати.

---

## 7. Локальний перегляд

```
python -m http.server 8898
```

Далі відкрити `http://localhost:8898`.

Відкривати `index.html` подвійним кліком не варто: частина речей
(посилання з параметрами, збереження стану конструктора) працює
лише через сервер.
